# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

sharp — self-hosted Slack replacement. Chat, collaborative docs & canvas, plus LiveKit SFU voice/video calls with screen sharing. Rust server (axum + sqlx/Postgres, optional Redis) serving both the REST/WebSocket API and the built React SPA from one binary. Monorepo: `server/` (Rust), `web/` (React+Vite+TS SPA), `desktop/` (Tauri 2 shell around the same web app), `landing/` (Astro static site), `deploy/` (docker-compose + Caddy), `docs/`.

**`docs/ARCHITECTURE.md` is the index to the contract** — invariants, a "where do I change what" table, and links into `docs/arch/*.md`, which hold the DB schema, wire types, every REST endpoint, every WS event, and the validation rules, split by feature. Read the index before any change that touches the API surface, then open only the feature file you need. Keep it updated in the same commit as the code — server, web, and desktop are each built against it independently.

**`docs/DESIGN_SYSTEM.md` is the single source of truth for UI construction.** All visual building blocks live in `web/src/ui/` (import from the barrel `../ui`) — buttons, inputs, modals, menus, badges, list rows, empty states, tokens, z-index bands, type scale. Read it before writing any styled JSX; never inline a class recipe a primitive already covers, never hard-code hex colors (theme presets break), extend the primitive + `/design` gallery + doc together when a variant is missing. Live catalog: `/design` route in dev builds.

## Where things live

Reach for the shared piece before writing a new one — `docs/ARCHITECTURE.md` has the full
"where do I change what" table. The ones most often re-derived by mistake:

- Channel authorization: the guards in `server/src/routes/mod.rs`, never a fresh
  `channel_members` query in a route module.
- Notification delivery: `notify.rs` (`insert_and_fanout` / `deliver_push`), never a push
  backend called directly.
- Outbound HTTP: `server/src/http.rs` — one pooled client.
- Env vars: `server/src/config.rs`, documented in `deploy/.env.example`, which is the
  canonical list.
- UI primitives: `web/src/ui/` (barrel `../ui`).
- Time/duration formatting and id comparison: `web/src/lib/util.ts`.
- Doc/canvas/board shell: `web/src/components/docs/DocSurface.tsx` — the three editors are
  bodies, not copies.

## Commands

```bash
./scripts/dev.sh          # one command: Postgres+Redis via Docker, server on :3000, web on :5173
```

Manual pieces:

```bash
# dev Postgres + Redis only
docker compose -f deploy/docker-compose.dev.yml up -d

# server (from server/)
DATABASE_URL=postgres://sharp:sharp@localhost:5432/sharp \
JWT_SECRET=dev-only-secret cargo run
cargo check               # fast compile check — no DATABASE_URL needed (no sqlx macros)

# web (from web/)
bun run dev               # :5173, proxies /api (incl. websocket) to :3000
bun run build             # tsc --noEmit && vite build — this IS the typecheck; run it to validate TS changes

# desktop (from desktop/)  — frontend is web/dist
bun run dev               # tauri dev (builds/serves web via `bun --cwd ../web`)

# landing (from landing/)
bun run dev / bun run build
```

**Bun is the JS package manager and script runner** (not npm/yarn) — `bun install`, `bun run <script>`, `bun.lock` lockfiles — everywhere: locally, in `deploy/Dockerfile*` (`oven/bun` images), and in GitHub Actions (`oven-sh/setup-bun`).

No lint config. Three validation gates: `cargo check`, `cargo test` (45 Rust unit tests — pure logic: camera/screen slot accounting, phrase streaks, trigger matching, notification previews, token hashing, webhook HMAC), and `bun run build` (tsc). The web app has no tests. Migrations in `server/migrations/` are embedded via `sqlx::migrate!()` and run automatically on server startup.

## Architecture essentials

- **sqlx runtime queries only — no `query!` macros.** Deliberate: keeps compilation independent of a live DATABASE_URL. Don't introduce macros.
- **Message IDs are Postgres `bigint` but serialized as strings** in all JSON (JS number safety). Channel/user IDs are UUIDs. Keep this invariant in both Rust models and TS types (`web/src/lib/types.ts` mirrors `server/src/models.rs`).
- **Realtime fanout**: `server/src/ws/` — in-process broadcast hub targeting member user-ids; if `REDIS_URL` is set, events also go through Redis pub/sub (`sharp:events`) for multi-replica sync. Every mutation route that changes visible state must emit the corresponding WS event (event lists live in `docs/arch/*.md`, starting with `01-core.md`).
- **Single binary serves everything**: API under `/api/v1`, plus the built SPA from `WEB_DIST` (default `./web-dist`) with SPA fallback; if the dir is missing it runs API-only.
- **Web state lives in one zustand store** (`web/src/store.ts` — state + actions). The WS event reducer is `lib/wsEvents.ts` (`applyWsEvent`, one flat switch that must stay in lockstep with `server/src/ws/`), the pure reducers are `lib/store/*Helpers.ts`, API calls are `lib/api.ts`, and the WS client with reconnect+backoff is `lib/ws.ts`; on reconnect the channel list is refetched. Every `sharp.*` browser-storage key lives in `lib/localPrefs.ts`.
- **Server URL resolution in the web app** (order matters): `VITE_API_URL` → `localStorage['sharp.serverUrl']` → `window.location.origin`. The desktop build leaves `VITE_API_URL` unset so users enter a server URL at login (Tauri detected via `'__TAURI_INTERNALS__' in window`).
- **Domain rules**: single workspace in v1; threads are one level deep (`parent_id` on messages, replies can't be parents); deletes are soft (`deleted_at` set, content blanked); unread counts count top-level messages only; DM channels are get-or-create with a generated hidden name and per-viewer `dm_user`.
- **Docs (Phase 2)**: collaborative BlockNote/Yjs docs living inside channels. The server persists/relays Yjs updates via `yrs` over a binary WS (`/api/v1/docs/{id}/sync`, custom frame protocol — see `docs/arch/02-docs.md`) with compaction of the `doc_updates` log; web side is `web/src/lib/docSync.ts` (provider) + `web/src/components/docs/`. Roles resolve owner (creator) > per-user override > `everyone_role`, and access changes revoke open sync sessions live. Bridging: `[[doc:<uuid>|<title>]]` chips in chat, `mention`/`doclink` inline content in docs, doc-mention inbox. **Keep Mantine on v8**: `@blocknote/mantine`'s Mantine v9 is React-19-only and crashes the editor under React 18.
- **Canvas (Phase 3)**: collaborative tldraw whiteboards built on the exact same doc foundation — a canvas **is a `docs` row with `kind = 'canvas'`** (migration `0006_doc_kind.sql`), reusing the same sync socket, permissions, and inbox. tldraw records live under `ydoc.getMap('tldraw')` (server never interprets them); web binding is `web/src/lib/tldrawYjs.ts` + `web/src/components/canvas/`. Compaction skips extracting text, so canvases have title-only search and no backlinks. **tldraw assets are self-hosted** (bundled by Vite) — no CDN; the editor chunk is lazy-loaded. The web app has a three-way **mode rail** (Chat `/`, Docs `/d/:id`, Canvas `/x/:id`).
- **Voice/video calls (Phase 4)**: ephemeral **LiveKit SFU WebRTC** rooms — one per channel/DM or an independent `standalone_calls` room, plus optional **webcam video** and **screen sharing** (with system/tab audio). Sharp authorizes joins, mints 60-second room tokens, coordinates state, and enforces **25 participants / 16 cameras / 1 screen share**; self-hosted LiveKit carries media using adaptive subscriptions, dynacast, and simulcast. Client engine is `web/src/lib/voice.ts`; UI is `web/src/components/voice/` (`VideoStage` adaptive grid/filmstrip + draggable/resizable + in-page fullscreen stage, `SpatialStage` floor plan, `CallChatRail`, `VoiceMiniWidget`). **Spatial audio**: positions are room state (`pos_x`/`pos_y` + `voice.move`), panning is a device-local listening choice — `voice.ts` routes remote mics through per-peer `PannerNode`s. **Mic control**: `voice.force_mute` mutes someone else for the whole room (muting only, any participant, confirm step in `ParticipantMenu`), "Mute for me" is playback-only (`setPeerLocalMuted`, both the `<audio>` element and the spatial gain node), and push-to-talk (`sharp.voicePushToTalk`, hold Space) runs through the single `setVoiceMuted` writer in the store. **Picture-in-picture** (`web/src/lib/pip.ts`): Meet-style Document PiP with element-PiP fallback so a call floats while you browse other channels. App state rides the existing main WS (`voice.*` events — see `docs/arch/04-voice.md`); `server/src/ws/voice/` owns the room registry (`mod.rs` join/leave/media + dispatch table, `polls.rs`, `annotate.rs`, `meeting.rs`). LiveKit config uses `LIVEKIT_URL`/`LIVEKIT_INTERNAL_URL`/`LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET`. **Transcription**: VAD-chunked MediaRecorder audio is proxied to an OpenAI-compatible provider, configured independently with `TRANSCRIBE_API_KEY`/`TRANSCRIBE_BASE_URL`/`TRANSCRIBE_MODEL` (falling back to matching AI settings). **Call links** (`server/src/routes/call_links.rs`): authenticated visitors keep their user session and use the link as admission proof; anonymous visitors get a limited, room-bound guest JWT (`web/src/components/GuestCall.tsx`).
- **Garden spatial rooms**: `/garden` is a Phaser-rendered, top-down spatial floor over ordinary non-DM channels. Its anti-aliased world uses the active Sharp theme; emoji stand in for replaceable scene assets, never controls. `garden_rooms` (migration `0035`) persist deterministic plot assignments; movement/presence are ephemeral on the main WS (`garden.*`). The map API omits private channels from non-members entirely. Entering a room may join that channel's existing LiveKit room with `garden_active=true`; Garden then owns voice spatial coordinates, keeps camera off, and never replaces an unrelated active call. Web lives in `components/garden/`; server lives in `ws/garden.rs` + `routes/garden.rs`; contract is `docs/arch/12-garden.md`.
- **Sharpy AI assistant (Phase 6)**: RAG chatbot over workspace content. Enabled iff `AI_API_KEY` set (OpenAI-compatible: `AI_BASE_URL`/`AI_CHAT_MODEL`/`AI_EMBED_MODEL`); fully inert otherwise. pgvector (migration `0022_sharpy.sql`, compose images are `pgvector/pgvector:pg16` now — the `vector` extension is required); dimension-less `vector` columns + exact cosine scan, so switching embed models means truncating the embedding tables. Self-healing 15s embed worker (no job queue) + immediate embed in `publish_message`; edit/delete hooks drop rows. Retrieval is ACL-filtered (`channel_members` join for messages, doc-role re-check for docs) — Sharpy must never surface content the asker can't read; encrypted DMs never embed. Server: `server/src/ai.rs` (embeddings + streaming chat client, and the OpenAI-compatible wire types `deepseek.rs` reuses), `server/src/routes/sharpy.rs`. Answers stream over SSE (`sources`/`delta`/`done` events) consumed via fetch-reader in `lib/api.ts`; UI is `web/src/components/SharpyPanel.tsx` slide-over (all modes) + home "Ask Sharpy" box + rail toggle. Query-embed failure degrades to a context-free answer (chat-only providers like DeepSeek work).
- **Tasks (Phase 7)**: Linear-lite tracker — **server-authoritative Postgres rows, NOT a Yjs doc kind** (migration `0023_tasks.sql`; the polls pattern: REST + `task.*`/`project.*` WS events broadcast to all users + notifications). Projects carry a `key`; identifiers (`SHARP-123`) allocate from `projects.next_number` in-transaction. Workflow states have fixed *types* (`backlog|unstarted|started|completed|canceled`) — automation and `completed_at` stamping target type, never name. Ordering = fracIndex strings (server mirrors `between(last, null)` in `routes/tasks.rs`). Server: `server/src/routes/tasks.rs` + `routes/github.rs`. Web: fifth **Tasks** rail mode (`/tasks`, `/t/:key`, `/t/:key/:num` peek), `web/src/components/tasks/` (list + board views, `useTaskDnd`). Chat bridging: bare identifiers auto-linkify against known project keys (Markdown.tsx), `[[task:<identifier>|<title>]]` chips, hover-toolbar "Create task" sets `source_message_id`, QuickSwitcher jumps. Notifications `task_assigned`/`task_comment` are channel-less (`notifications.channel_id` now nullable + `task_id` column). **GitHub sync** is self-serve per project (migration `0034`, `project_github_repos` + `projects.branch_template`): each link owns a generated webhook secret, so no env var or restart is needed, and matched links scope automation to their own project keys; an optional PAT (sealed with `calendar_crypto`) lets the server verify the repo, read visibility, and install the webhook via `server/src/github_api.rs`. `GITHUB_WEBHOOK_SECRET` (+ optional `GITHUB_REPOS`) stays as a global fallback. HMAC-verified webhook links branches/PRs by identifier in branch/title/body and moves states (started on branch/PR, completed on merge); branch convention is `projects.branch_template`; UI is `web/src/components/tasks/ProjectGithub.tsx`. Sharpy embeds tasks via `task_embeddings` (migration `0024`).
- **Notifications + web push**: `server/src/notify.rs` turns a new message into inbox rows + `notification.created` WS events + push to offline recipients. Kinds: `dm`, `mention` (`@Display Name` / `@all`), `reply`, `poll_ended`, `task_assigned`, `task_comment`. **Granular prefs** (migration `0026`): per-channel mode (`all`/`mentions`/`muted`), per-type master switches (`notify_{dm,mention,reply,task,poll}` — disabled type = no row at all), and DND that is either the manual toggle or a scheduled quiet-hours window (`dnd_scheduled`+`dnd_start`/`dnd_end` minutes-of-day local via `tz_offset`). All enforced in `notify.rs` (`channel_allows`/`kind_enabled`/`is_dnd`); DND keeps the inbox row+WS but suppresses push; managed from **Settings → Notifications** (`web/src/components/settings/NotificationsSettings.tsx`; `UserSettingsModal.tsx` is only the shell + tab registry, store helper `dndActive()`). Web push uses the `web-push` crate (VAPID/RFC 8291); keys resolve env → `app_meta` persisted → auto-generated (`server/src/vapid.rs`), zero-config. Public key at `/push/vapid`; service worker `web/public/sw.js`; dead subs (404/410) pruned. **Native macOS push (APNs)**: `server/src/apns.rs` (token-based ES256 `.p8` JWT cached ~50 min + reqwest HTTP/2, prunes 410/BadDeviceToken), env-gated by `APNS_*` (inert unless all set), stored in `apns_tokens` (migration `0027`), gated on no-visible-session like web push. The Tauri desktop shell registers via `tauri-plugin-notifications` (community superset that **replaced** the official `tauri-plugin-notification` — they can't coexist; provides local notifications too) and `web/src/lib/apns.ts` POSTs the hex token to `/push/apns/register` — **best-effort: only works in a signed/notarized build with the `aps-environment` entitlement + Push-capable App ID; unsigned builds fall back silently** to WS + local + web push.
- Auth: JWT HS256, 30-day expiry, `Authorization: Bearer` on REST, `?token=` on the WS URL. First-user registration is always allowed even with `SHARP_DISABLE_SIGNUP=true`.
- **Social sign-in (Google, GitHub)**: native OAuth 2.0 authorization-code flow in Rust — `server/src/social_oauth.rs` is protocol only, `server/src/routes/social_auth.rs` owns all policy, and the result is an ordinary sharp JWT so no other surface changes. Identity is `(provider, provider_user_id)`, **never the email**; linking to an existing account demands a provider-*verified* email; a first-time identity is a signup and obeys `SHARP_DISABLE_SIGNUP`; the callback hands the SPA a single-use 60s code (`auth_handoff_codes`, migration `0036`) instead of putting a JWT in a URL. `state` is a provider-pinned HS256 JWT, plus an HttpOnly nonce cookie for sign-in flows (login CSRF). `users.password_hash` is now **nullable** — social-only accounts have none, so password login, passkey enrolment and unlinking all guard for it. Env gate is the redirect URI (`OAUTH_GOOGLE_REDIRECT_URI` / `OAUTH_GITHUB_REDIRECT_URI`), which is what keeps a Calendar-only Google client from advertising a broken login button. Desktop reuses the existing `sharp://auth?code=` bridge from `desktop_auth.html`; contract is the "Social sign-in" section of `docs/arch/01-core.md`.
- **Password reset**: self-service email flow, env-gated — inert (link hidden) unless `EMAIL_FROM` plus one backend is set. `server/src/mailer.rs` is a two-variant `Mailer` enum: **Resend HTTP API** (`RESEND_API_KEY`, optional `RESEND_BASE_URL`; preferred — no outbound SMTP ports, and it wins when both are configured) or **SMTP** (lettre/rustls: `SMTP_HOST`, `SMTP_PORT` default 465, `SMTP_USERNAME`/`SMTP_PASSWORD`, `SMTP_TLS=implicit|starttls`). `SMTP_FROM` stays accepted as an `EMAIL_FROM` alias. Resend rejects sends from an unverified `EMAIL_FROM` domain. `POST /auth/password/forgot` always 200 (no user-enumeration) + mails a 1h link to `/reset-password?token=`; only SHA-256 of the raw token is stored (migration `0028`, `password_reset_tokens`). `POST /auth/password/reset` sets the hash + burns the user's tokens. Email links use `APP_URL` if set, else the request Origin/Host. Web: "Forgot password?" affordance on `Login.tsx` (gated on `GET /auth/password/config`) + public `ResetPassword.tsx` route. No admin/reset-by-admin path exists; passwords are argon2, never recoverable.
- **Desktop browser-login flow**: the Tauri app authenticates in the system browser, not an embedded form. It opens `<server-url>/desktop-auth?state=&scheme=` (a self-contained page served by the API from `server/src/desktop_auth.html`, so it works even in a split deploy where the SPA is on another subdomain); after login the page calls `POST /auth/desktop/code` (mints a one-time 60s code bound to the caller), then deep-links back via `sharp://auth?code=&state=`; the native app calls `POST /auth/desktop/exchange` (unauthenticated, single-use) to get its JWT. Web glue is `web/src/lib/desktopAuth.ts`. One-time codes are in-process/per-replica.

## Deploy

`deploy/docker-compose.yml` (Caddy/VPS) or `deploy/docker-compose.dokploy.yml` (Dokploy/Traefik — see `deploy/DOKPLOY.md`). Multi-stage `deploy/Dockerfile` builds web then server into one image. `deploy/docker-compose.local.yml` runs the full stack without host Rust/Node.
